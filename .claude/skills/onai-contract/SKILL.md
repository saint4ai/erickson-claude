# Договор Erickson

Договор ты не сочиняешь. Текст утверждён Erickson и лежит в трёх шаблонах в `assets/`: «Level 1 онлайн.docx», «Level 1 оффлайн.docx», «Level 2 оффлайн.docx». Шаблоны только на русском, казахских Erickson пока не дали. Если просят договор на казахском, скажи, что нужен утверждённый казахский шаблон от Erickson, сам не переводи. Твоя часть: выбрать шаблон и собрать данные. Заполняет и проверяет скрипт `scripts/fill_contract.py`. Запускай его из корня папки проекта по пути `.claude/skills/onai-contract/scripts/fill_contract.py`; путь к шаблону `assets/<шаблон>.docx` скрипт сам считает от папки навыка.

## Сначала: личные данные клиентов

Через тебя идут ИИН, удостоверения и реквизиты клиентов Erickson. Это правило выше всех остальных шагов.

- На тарифе Team этот вопрос не задавай: там чаты на обучение модели не идут. На личном тарифе до того, как сотрудник пришлёт документы клиента, один раз за разговор спроси: «В настройках Claude выключено Help improve Claude? Если включено, данные клиентов могут пойти на обучение модели». Путь: Settings → Privacy → Help improve Claude. Если не выключено или сотрудник не знает, объясни, где выключить, и продолжай только после этого. Там же предупреди: не ставить 👍/👎 на ответы с данными клиентов, такой отзыв хранится у Anthropic до пяти лет при любой настройке.
- Из документов бери только поля, которые просит шаблон. Остальное не переписывай и не пересказывай.
- Данные клиента не ищи в интернете и не передавай в другие подключённые сервисы.
- Когда договор выдан, удали `data.json`.

## Порядок

1. Один раз за разговор проверь, что всё готово: `python3 -c "import docxtpl, num2words"`. Если не хватает библиотек, поставь их: `python3 -m pip install --user docxtpl num2words`. Если pip ругается на externally-managed, добавь `--break-system-packages`. На Windows вместо `python3` пиши `python`. Если Python нет совсем, объясни сотруднику, что его надо поставить с python.org, и помоги.

2. Выбери шаблон по программе и формату обучения (`python3 .claude/skills/onai-contract/scripts/fill_contract.py templates` покажет список). Не ясно, какой нужен, спроси. Узнай поля: `python3 .claude/skills/onai-contract/scripts/fill_contract.py fields --template "assets/<шаблон>.docx"`. В `collect` то, что нужно собрать. Поля из `computed` скрипт посчитает сам.

3. Собери данные из того, что прислал сотрудник:
   - ФИО, ИИН/БИН, адреса, реквизиты бери только из документов и сообщений клиента. Цифра на фото читается плохо — спроси, не угадывай.
   - Цену (`price_base`) бери из файла «Каталог программ и цен» в папке проекта. Если эта цена в разделе «Что не сходится» или сотрудник называет другую, покажи расхождение и спроси, какую брать. Скидку и график траншей называет сотрудник. Сам скидку не предлагай.
   - Шаблон договора рассчитан на обучающегося физлица. Если платит компания, предупреди: в шаблоне нет полей плательщика-компании, это решает Erickson.
   - Плательщиком может быть сам обучающийся, другой человек или компания. Если из присланного это не ясно, спроси.
   - Номер договора называет сотрудник. Если приложен реестр, предложи следующий номер по нему и спроси.

   Чего не хватает, спроси одним списком.

4. Покажи сотруднику собранные данные таблицей и дождись подтверждения.

5. Запиши `data.json` в корень папки проекта (не в папку навыка) и запусти из корня:
   `python3 .claude/skills/onai-contract/scripts/fill_contract.py fill data.json --template "assets/<шаблон>.docx" --out "Готово/Договор <фамилия> <имя>.docx"`
   Папка выдачи — `Готово` в папке проекта. В обычном чате Claude — та, из которой ты отдаёшь файлы пользователю.

   Даты пиши ГГГГ-ММ-ДД, суммы целыми тенге:
   ```json
   {
     "contract_date": "2026-10-27",
     "price_base": 2600000,
     "discount_percent": 10,
     "payments": [
       {"date": "2026-11-20", "amount": 1170000},
       {"date": "2026-12-20", "amount": 1170000}
     ],
     "student_name": "Имя Фамилия",
     "остальные поля из collect": "значения строками"
   }
   ```
   Скидка: `discount_percent` или `discount_amount`, только одно. Без скидки не пиши ни то, ни другое.

6. Если скрипт отказал, покажи сотруднику причины как есть и исправьте данные вместе. Проверку не обходи, готовый файл вручную не правь.

7. Когда договор собран, отдай файл и под ним:
   - строку для реестра договоров: номер, дата, плательщик, обучающийся, программа, цена, скидка, итог, число траншей;
   - строки для таблицы платежей, по одной на транш: номер договора, плательщик, номер транша, дата, сумма.

   Если сотрудник приложил реестр, добавь строку в его колонки и верни файл. Транши предложи сразу внести в таблицу платежей навыком `onai-payments`.

## Нельзя

- Отправлять договор клиенту. Отправляет сотрудник после своей проверки.
- Менять текст договора, добавлять пункты, переводить формулировки. Нужен другой текст — это правка шаблона, её делает Erickson.
